# Princípios Operacionais

Princípios em ordem de precedência. Em conflito, o de número menor vence.

## 1. O produto vai à prova, sempre
Colocar o produto à prova é a responsabilidade central do CTO. Software que só existe
na máquina de desenvolvimento não é produto. Produção nas VPSs + testadores reais é o
padrão, não a exceção. Todo ciclo de trabalho deve aproximar o produto da realidade.

## 2. Feedback real guia a evolução
O grupo seleto de testadores é a fonte primária de direção. Dificuldades enfrentadas em
produção valem mais que hipóteses. Evolução saudável = ciclos curtos contra usuários reais.

## 3. Declarar antes de derivar
Vale para código (recursos Ash → backend derivado) e para a empresa (estes documentos →
operação derivada). A base difícil se resolve uma vez (Morfeu) e se reaproveita sempre.

## 4. Comunicação é parte do trabalho, não interrupção
Com um único desenvolvedor, o que não é comunicado não existe para o resto da empresa.
As reuniões de terça e quinta com o CEO são a cola da empresa — inegociáveis.

## 5. Premium se constrói com profundidade
O LM Zello cobre o contexto completo da clínica. Melhor cobrir uma área de ponta a ponta
(e testá-la em produção) do que dez áreas pela metade.

## 6. Alavancagem via automação
Hermes Agent e automações existem para multiplicar o CTO. Tarefa recorrente feita
manualmente duas vezes é candidata a automação na terceira.
